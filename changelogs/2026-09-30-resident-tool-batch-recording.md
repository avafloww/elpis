# Forensic resident tool-batch recording

Elpis now instantiates one process-local resident-run provenance authority and gives only its issuer to the main Agent. For each live assistant response containing tool calls, Agent creates a fresh batch commitment over ordered tool names and exact raw-argument hashes, writes the forensic record on the assistant transcript message, and commits the prepared batch only after the synchronous transcript append succeeds. If that append fails, the batch is not committed and no tool executes. A provider batch outside the provenance bounds is appended without a batch record, each call receives a rejection result, and the long-lived loop continues without executing the invalid batch.

Restart parsing accepts the metadata only on an assistant message with valid tool calls and only when the strict record parser recomputes the same commitment. Changed arguments, wrong roles, extra fields, and malformed records lose the forensic field while the ordinary message remains usable. Restored records cannot recover process-local authority. Provider translators continue building fresh wire messages and omit the harness-only field.

This stage does not issue per-call tokens, pass a verifier to the sandbox manager, create run-scope provenance, expose a sandbox API, add a database schema, or grant profile, provider, tool, effect, activation, or identity authorization. Focused production-path tests cover transcript round-trip and rejection, append-before-commit ordering, no execution after append failure, oversized-batch rejection without loop failure, and provider-field omission.
