# Assemble the first current-world dark request

A live resident run now has `elpis.context.assembleCurrentWorldDarkRequest()`. The zero-argument action uses only the run's captured wake-defining Discord or Signal lineage, the exact stored text projection, and the accepted current world profile/head. In one transaction it admits that event, assembles a profile-bound branch and non-runnable provider-neutral request candidate, records a recoverable pending attempt, and returns the complete exact candidate for inspection.

The action does not call a provider, grant or issue tools/effects, create a capsule, activate graph routing, or advance continuation. Presentation overflow or secret-redaction changes roll the transaction back. Exact same-call retry rereads the same stored candidate. A successful call deliberately leaves one running dark branch; after deployment, verify the candidate and exercise controlled restart recovery before building the next lifecycle seam.

No database migration or configuration change is required. Focused store, presentation, authority, idempotency, rollback, and recovery tests cover the new path; full validation is recorded with the shipping commit.
