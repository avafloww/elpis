# Dark isolated-provider invocation admission

Schema v49 adds an immutable invocation-admission receipt for an exact dark isolated-provider binding. The receipt rematerializes and copies the bound branch, request view, profile, manifest, candidate, target, and cache lineage, and fixes a one-attempt isolated policy with no transport retry, surface fallback, tools or historical tool messages, network authority, effects, capsules, or continuation authority.

`ContextGraphStore.admitDarkIsolatedProviderInvocation()` admits only the exact current running coordinator branch in dark mode, with no abandonment, recovery, later profile revision, effects, capsules, or continuation advance. Exact same-input replay is idempotent before or after branch recovery; a changed timestamp or other candidate field conflicts rather than silently reusing the existing receipt. The admission copies the resident and request profile bindings, manifest cache namespace, canonical target, and all other binding lineage needed for strict typed rematerialization.

This change adds no resident tool, Agent call site, provider adapter, credential access, network dispatch, output persistence, capsule creation, activation, or continuation behavior. Provider execution remains unwired until dispatch commitment, issuance disposition, raw outcome, and startup recovery semantics are implemented and separately reviewed. Canonical call timeout, stream-idle timeout, and output-size limits do not yet exist for the isolated lane; choosing and snapshotting those limits is an explicit blocker before any dispatcher can make these admissions runnable.
