# Repair worker completion wakes

A worker finish now commits the durable mailbox row and terminal session state in one transaction, then emits a body-free reconciliation hint. The resident receives a distinct `worker` synthetic pointer with `observe_only` send authority; delegated report text, runtime diagnostics, and artifacts remain available only through explicit worker status and artifact lookups. Status always retains the unique finish within its 100-message bound, and follow-up reads the finish directly. Exact finish retries return the original receipt, while every other worker capability is revoked after terminal commit.

Recovery now gives committed dismissal first precedence and valid durable finish second precedence. Pod failure, disappearance, UID changes, or later broker errors cannot overwrite a finish; a Pod that succeeds without a finish is a protocol failure. Already-persisted terminal notices bypass active Pod inspection and detached cleanup, including during supervisor activation. Disposal synchronously terminalizes every locally provisioning session and revokes its worker token before aborting in-flight provision, inspection, and cleanup; a provision that returns or rejects afterward is compensated with exact Pod and Secret cleanup, while restart retries any interrupted cleanup instead of adopting that Pod. Concurrent cleanup callers join one retryable effect, with rollback-safe completion time and bounded failure visible through worker status. Active finished Pods receive a process-monotonic 30-second cleanup grace that remains bounded if the wall clock moves backward. Dismissal waits for locally owned Pod creation before cleanup, while a finish committed during creation remains terminal. Schema v28 grandfathers legacy terminal delivery state but leaves every legacy runtime cleanup receipt pending for idempotent recovery.

Focused mailbox, HTTP, supervisor, Agent provenance/send-denial, Kubernetes abort, recovery, cleanup, and v27→v28 migration regressions pass, along with TypeScript build validation. Deployment should verify that a real worker finish wakes the resident without status polling, that the worker receives its finish receipt, and that later cleanup does not change the terminal result.
