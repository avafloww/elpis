# Add inert Codex WebRTC response correlation

The Codex app-server voice broker can now issue the exact client-managed `thread/realtime/appendSpeech` request for its active thread. A new injected adapter correlates ordered WebRTC control events and bare PCM with the resident voice session's exact request, response, and output-item ownership.

Successful delivery is authorized only by a matching `output_audio_buffer.stopped(response_id)` after completed generation; raw `response.done` is non-delivery terminal state. Interrupted and stale terminal interleavings retain bounded response and output-item tombstones; only a typed assistant `output_audio` message can own bare PCM, while audio-specific event IDs remain non-authorizing references. In-flight PCM after cancellation or failure is discarded until the exact media terminal and remains fatal afterward. A cancelled or failed media owner must reach an exact `stopped` or `cleared` terminal before another cross-transport handoff, including through reentrant cancellation callbacks. Active cancellation uses a bounded correlated event ID, ignores only its matching not-active race, and always dominates a later completed status. A media terminal delivered reentrantly by the response-cancel send suppresses the otherwise subsequent global clear, keeping every cross-transport clear behind an acknowledged barrier. Post-terminal unowned PCM fails closed, finalized input remains ordered, and consumed input deletion is forwarded as `conversation.item.delete`. Local player drain still precedes a `played` receipt.

This slice is inert. It adds no configuration, command/controller wiring, process factory, provider selection, authentication, device, network, or call effect. Subscription-backed handoff and real Discord call acceptance remain activation prerequisites.
