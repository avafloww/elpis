# Console v2 adjustment ledger

This ledger records deliberate differences between the v2 design handoff and the production console. It is not a backlog: each entry names the functional reason for the divergence.

1. **Preact + esbuild, not the design runtime or Vite.** The `.dc.html` runtime is reference-only. The production console is one authenticated static origin with one WebSocket and stable asset names, so Preact owns components/state while an explicit esbuild step emits `app.js` and `app.css` into `dist/console/public`. Vite's dev-server conventions, generated asset indirection, and broader pipeline would add seams without adding runtime capability here.
2. **Server receipts replace prototype timers.** Worker dismiss, steering delivery, secretary start, turn states, chat send, and proposal creation render real backend states and request-correlated results. The prototype's 600–1900 ms fixture delays are not copied.
3. **Secretary launch context is not authority scope.** “Ask secretary about this” supplies an optional Mind item as prompt context. The secretary remains a global authorized-Mind reader with fixed proposal-create authority; it is never confined to the launching item's subtree.
4. **Secretary proposals are host-validated writes.** The prototype says the secretary never writes Mind directly while simulating proposal creation. Production exposes only a fixed proposal-create operation whose requester/source/session metadata and proposal invariants are enforced by the host. It exposes no general Mind mutation.
5. **Dark v2 palette is the product surface.** The retired console's separate light theme is not carried forward. This keeps the handoff's exact color hierarchy and removes a second unmaintained visual system.
6. **Live data may be honestly thinner than fixtures.** A view shows unavailable, stale, empty, or bounded-history states when the Hub does not expose a fixture field. It never synthesizes worker events, room counts, context segments, proposal links, or model activity to fill the mockup.
7. **Run source stays authored, not browser-reformatted.** Tool calls render the exact source carried by the Hub. The retired console's in-browser Prettier/Prism runtime and heredoc placeholder restoration are not copied, avoiding a second formatting policy and a large client payload; result splitting and execution attribution remain typed code.
